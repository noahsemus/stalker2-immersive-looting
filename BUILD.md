# Building ImmersiveLooting (Zone Kit pak)

For anyone who wants to rebuild, modify or extend the mod: what it changes, exactly how, and how to cook it.
Toolchain, cook rules and traps shared by all our mods are in [harness/docs/pipeline.md](harness/docs/pipeline.md)
and [harness/docs/blueprints.md](harness/docs/blueprints.md); the player-animation facts this mod relies on are in
[harness/docs/animation.md](harness/docs/animation.md).

## 1. Prerequisites
- S.T.A.L.K.E.R. 2 Zone Kit (Epic Games Store), ~600 GB free. First launch compiles shaders for a long time.
- Git. No Python install needed (the kit ships 3.11).
- Run `harness\tools\setup.ps1` once: it finds your Zone Kit and game and stores them outside the repo.

## 2. What the mod is
A Zone Kit plain-mod plugin `ImmersiveLooting` (`zonekit/ImmersiveLooting/`, mirrored from the kit). Nothing of the
game is overridden; the only override-container package is the plugin's own subsystem registration.

| File (under `Content/`) | Kind | Container | What it does |
|---|---|---|---|
| `Autogenerated_1791594822_WorldSubsystemData` | ModWorldSubsystem data asset (made by the kit when the mod is picked in the toolbar selector) | OverrideContent (`zzz_ImmersiveLooting_20_P`) | Registers `BP_ImmLootSubsystem` with the game |
| `Runtime/BP_ImmLootSubsystem` | Blueprint, ModWorldSubsystem | NewContent | Ticks; spawns `BP_ImmLootActor` whenever it is missing (`zonekit/tools/gen_subsystem_spawn.py`) |
| `Runtime/BP_ImmLootActor` | Blueprint, Actor | NewContent | All the logic (section 4); event graph generated by `zonekit/tools/gen_actor_looting.py`, variables by `setup_assets.py` |
| `Runtime/AS_ImmLoot_Grab` | AnimSequence, copy of the vanilla `ar/common/grabitem/fp_ar_weapon_grab` | NewContent | Loose-item grab with a weapon in hand: the left arm re-solved so the hand rises into view at the crosshair; HandIK notifies (off 0.036 s, on 1.179 s) and the curve `left_hand_curve` (`make_grab_seq.py`) |
| `Runtime/AS_ImmLoot_GrabBH` | AnimSequence, 120 segments x 1.5 s | NewContent | Loose-item grab with empty hands: one segment per (elevation, distance, azimuth) of the item seen from the eye in the body frame; the Blueprint starts the montage at the segment (`make_grab_seq.py build_bh_reach_table`) |
| `Runtime/AS_ImmLoot_Touch0..24` | AnimSequence, 1.67 s each | NewContent | Corpse / stash touch with a weapon: hand from the grip toward the target's direction in view axes (elevation -45..+15 x azimuth -30..+30, 15 deg bins), HandIK off / on, `left_hand_curve` (`make_grab_seq.py build_touch`) |
| `Input/IA_ImmLootInteract`, `Input/IMC_ImmLoot` | InputAction (bool, consumes input), InputMappingContext | NewContent | Our interact: the context is added only while a corpse / stash is in sight, with the player's own interact keys copied in at runtime (`QueryKeysMappedToAction` + `MapKey`) |

## 3. Build from the committed source
1. `powershell -File harness\tools\deploy_to_kit.ps1` (plugin + classifier lists into the kit).
2. Start the editor once and pick `ImmersiveLooting` in the toolbar mod selector (mounts the plugin, creates the
   subsystem data asset).
3. `powershell -File harness\tools\cook_and_install.ps1` (cook, then install as `~mods\zzz_ImmersiveLooting_PakTest\`).
Release zips (`harness/tools/make_release.py`) ship the override container as `zzz_ImmersiveLooting_20_P.*` and the
NewContent container under the kit name.

To rebuild the assets themselves instead of using the committed `.uasset`s (editor open, Python remote execution on):
1. `run_headless.ps1 -Script zonekit\tools\setup_assets.py`: the two Blueprints with their variables and defaults,
   the input action and context, the actor's `auto_receive_input`.
2. `ue_exec.py zonekit\tools\make_grab_seq.py`: `AS_ImmLoot_Grab`, `AS_ImmLoot_GrabBH` (`--arg BH=0` to skip, slow),
   `AS_ImmLoot_Touch0..24` (`--arg TOUCH=0` to skip).
3. `gen_subsystem_spawn.py` / `gen_actor_looting.py <out.txt>` write the event graphs as paste text; in each
   Blueprint: select all in the event graph, delete, paste, compile, save. `check_paste.py` lints the text,
   `compare_graph.py` checks the saved graph against it.

## 4. The edits, asset by asset
Every node and pin is in the generators (the paste text is the specification); this is the behaviour they encode.

**`BP_ImmLootActor` (Event Tick, `TG_PostUpdateWork`), in order each tick:**
0. Once: load `IMC_Inventory` (the loot window's context) for step 2.
1. Picked up? The loose item looked at (step 4, seen < 0.3 s ago) is gone (destroyed, mesh hidden or moved 1.5 m):
   mark a reach with a flying copy.
2. Loot window: `IMC_Inventory` applied = open; the target cached the tick before says corpse (`DeadBody`
   component) or stash (`InteractableItemContainer` owner that is not a loose-item class). Closed = context gone
   0.25 s and the view hidden (or 3 s). On close, if our touch is out: play the montage on (weapon: its own path
   back to the grip, its "hand back on" IK notify re-grips) or backwards (empty hands), then clear the touch.
   Touch steps: add `IMC_ImmLoot` while a corpse / stash is in sight (copying the player's interact keys once),
   remove it otherwise; when the touch is held (paused 0.25 s at 0.6 s montage time) or 2 s after the press,
   remove the context and `InjectInputForAction(IA_Interact)` so the game opens its window; if no window appears
   within 1 s, bring the hand back.
3. Pending reach: skip while sprinting, aiming, a `MainActionSlot` action or another LeftHand montage runs, in
   dialogue or cutscene, detector or binoculars in hand (vanilla pickup). Else play in slot `LeftHand` as a dynamic
   montage (blend in 0.2, out 0.7, rate 1.15): weapon in hand = `AS_ImmLoot_Grab` (loose item) or the touch asset
   picked at the press; empty hands = `AS_ImmLoot_GrabBH` started at the segment for the item's (elevation,
   distance, azimuth) from the eye in the mesh frame, stopped 1.35 s later.
4. Track the loose item under the crosshair (`PC.GetInteractedActor`): actor, mesh component / asset, transform,
   bounds centre.
5. The flying copy (`StaticMeshActor` / `SkeletalMeshActor` spawned where the item was) stays put until the grab
   frame (0.40 s montage time), is pulled to the bone `jnt_l_weapon` in 0.12 s, attached there (snap location,
   keep rotation and scale) and destroyed at the pocket frame (0.87 s).
6. End steps: stop the empty-hands segment at its end; hold the touch at 0.6 s (`Montage_Pause`); when playing
   backwards reaches the segment start, stop; recovery: our montage cut before its IK-on notify with a weapon held
   and no other LeftHand montage -> play the vanilla `MG_fp_return_left_hand_on_item`.

**Interact press (`IA_ImmLootInteract` Started)** while our context is on: if idle and the corpse / stash part is
known: target = its `jnt_hips` bone for a skeletal mesh that has one (a dead body's component bounds stay at the
standing position), else the component's bounds centre; its direction in view axes picks `AS_ImmLoot_Touch<ie*5+ia>`
into `TouchAsset`; mark a reach without a copy. Otherwise pass the press on (remove the context, inject interact).

**Variables** (`setup_assets.py ACTOR_VARS`): settings `PlayRate` 1.15, `GrabTime` 0.40, `PocketTime` 0.87,
`IKOnTime` 1.179, `SeenWindow` 0.3, `TouchHoldBeforeOpen` 0.25 (montage seconds; real = montage / PlayRate), plus
state and probe counters (read by the dev probe `zonekit/tools/probe/ImmLootProbe`, UE4SS, never shipped).

**`BP_ImmLootSubsystem`:** `On Initialized` -> `Set Tick Enabled(true)`; `On Tick` -> if `LootActor` is not valid,
`SpawnAttempts += 1` and spawn `BP_ImmLootActor`.

**Animation assets** (`make_grab_seq.py`, numbers in the script): the left arm (`jnt_l_arm`, `jnt_l_fore_arm`,
`jnt_l_hand`) is re-solved per frame with a two-bone IK toward a target, the hand keeping a blended rotation; all
other bones are the vanilla grab's. With a weapon in hand the arm rig follows the view, so targets are relative to
the camera bone (= view axes in game, with the measured landing map ahead + 8.4 cm, right x 1.14 + 4.0, up x 1.15
+ 2.0); with empty hands the arms stay in the body frame, hence the table by elevation / distance / azimuth, aimed
short by the measured bias (9, 15, 5).

## 5. Traps specific to this mod
- A `LeftHand` montage without the curve `left_hand_curve` plays but never moves the hand on rifles with an
  underbarrel idle (the weapon layer pins the left arm to its grip pose weighted by 1 - the curve). Every
  mod-made LeftHand sequence here carries the curve.
- The vanilla "hand back on the item" IK notify must not play with empty hands (the hand jumps to the invisible grip):
  `AS_ImmLoot_GrabBH` has IK-off notifies only.
- `Montage_IsActive` is false for a paused montage: the touch logic checks `IsValid(GrabMontage)` instead.
- The 180 s rifle-stance reach table (`AS_ImmLoot_GrabAR`, deleted) never showed over a rifle; many short sequences
  (~15 KB each cooked) are used instead.
- The interact intercept consumes the key only while our context is on (a corpse / stash in sight); holding the key
  (drag a body) still reaches the game because the press is injected on through `InjectInputForAction`.
- `BlueprintInternalUseOnly` nodes (`VEase`) and impure library calls (`GetScalarParameterValue`) are dropped or
  pruned when pasted; the generators avoid them (see harness/docs/blueprints.md).
